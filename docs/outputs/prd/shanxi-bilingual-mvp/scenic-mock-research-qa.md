# 山西景区 Mock 数据 — 调研 Q&A（交给网页 GPT）

> 用途：把本文**整份**或按章节粘贴给网页端 GPT，请其按「可写入小程序 Mock」的结构回答。  
> 项目：山西文旅景区介绍与双语服务小程序（入境游客跨文化体验）  
> 语言：每个内容字段都需要 **中文 + 英文**；英文须自然、面向外国游客，避免机翻腔。  
> 输出要求：优先用表格或 JSON 友好结构；不确定处标注 `UNVERIFIED`，并给出可核对的公开来源链接（官网/文旅局/UNESCO 等）。

---

## 使用说明（给你自己）

1. 可一次贴全文，或按「A → B → C…」分批提问以免超长。  
2. GPT 回报后，把原文/整理稿发回 Cursor，再落成 `mock` JSON 或 SQL seed。  
3. 图片：本阶段只要**图注与可公开引用的图片 URL 建议**；不要让 GPT 生成假版权图文件。

---

## A. 景区清单（先定 Mock 覆盖哪些点）

**A1.** 请列出适合作为「山西文旅双语小程序」演示的 **8～12 个**重点景区/遗产点，要求：

- 覆盖：世界遗产或全国重点、5A/知名 4A、不同城市（至少太原、大同、晋中/平遥相关、运城或临汾其一）
- 类型尽量多样：古建、石窟、古城、自然/黄河或太行相关、晋商文化等
- 对每个点给出：中文名、英文名、所在地级市、建议优先级（P0 必做 / P1 可延后）、一句话为什么适合入境游客

**A2.** 若只能做 **6 个 P0**，你会删掉哪些？保留理由是什么？

**A3.** 以下名称是否应单独成条，还是并入某景区的「子景点/看点」？请给建议：

- 云冈石窟、悬空寺、平遥古城、乔家大院、晋祠、五台山、壶口瀑布、雁门关、王家大院、应县木塔、皇城相府、解州关帝庙（可增删）

## B. 单景区字段模板（每个 P0 景区都填一套）

对 **每个 P0 景区**，请按下列字段输出（中英成对）。缺信息标 `UNVERIFIED`。

| 字段 key | 说明 |
|---|---|
| `id` / `slug` | 英文短横线 slug，如 `yungang-grottoes` |
| `nameZh` / `nameEn` | 官方或通行名称 |
| `cityZh` / `cityEn` | 地级市 |
| `level` | 如 5A、世界遗产等（注明依据） |
| `tags` | 3～6 个标签（中英），如 石窟 / Grottoes |
| `summaryZh` / `summaryEn` | 80～120 字简介（英文 60～90 words） |
| `introZh` / `introEn` | 较长介绍 200～400 字（英文相应） |
| `highlights` | 3～5 条看点，每条 `{ zh, en }` |
| `openTimeZh` / `openTimeEn` | 开放时间（含淡旺季若常见） |
| `ticketZh` / `ticketEn` | 门票概要（价格区间即可，注明是否需预约） |
| `transportZh` / `transportEn` | 如何到达（高铁/机场/市内交通要点） |
| `bestSeasonZh` / `bestSeasonEn` | 适宜季节与气候提示 |
| `visitTipsZh` / `visitTipsEn` | 参观实用提示（安检、着装、拍照规定等） |
| `culturalNotes` | 见下一节 C（可内嵌） |
| `services` | 见下一节 D（可引用条目 id） |
| `geo` | 大致 lat/lng（可近似，标 UNVERIFIED） |
| `coverImageHint` | 封面图应拍什么 + 建议检索关键词（中英） |
| `sources` | 2～5 个可核对来源 URL |

**B1.** 请先给出 **空白 JSON Schema 示例**（一个景区对象），再填 **全部 P0 景区** 的完整数据。

**B2.** 门票与开放时间若各地政策常变：请写「典型公开信息 + 提醒以景区当日公告为准」的中英固定句式，供 UI 复用。

## C. 文化解读与跨文化障碍（课题对齐）

**C1.** 针对入境游客在山西文旅场景，归纳 **6～10 类**常见「跨文化体验障碍」，每类：

- 名称（zh/en）
- 表现（游客会遇到什么）
- 小程序可用什么内容缓解（对应功能：文化解读 / 服务话术 / 参观提示）

**C2.** 对每个 P0 景区，写 `culturalNotes` 数组（至少 3 条），每条：

```text
{
  "barrierType": "障碍类型 id 或名称",
  "titleZh": "", "titleEn": "",
  "bodyZh": "", "bodyEn": "",
  "doZh": "", "doEn": "",      // 建议做
  "dontZh": "", "dontEn": ""   // 避免做
}
```

覆盖尽量包含：宗教/礼仪场所举止、古建保护与触摸禁忌、拍照规定、排队与购票习惯、饮食/酒文化若相关、历史语境（为何重要，而非仅年代数字）。

**C3.** 五台山、关帝庙等宗教相关场所：请单独给出「外国游客礼仪」中英短文（可复用到多景区）。

## D. 双语服务条目（话术 / 指引）

**D1.** 设计 **12～20 条**通用 `bilingualServiceItems`（不绑单一景区），分类建议：

- 购票与预约  
- 问路与交通  
- 餐饮与过敏  
- 紧急求助  
- 礼仪与禁止事项  
- 购物与议价（若适用）  

每条字段：

| key | 说明 |
|---|---|
| `id` | 如 `svc-ticket-ask` |
| `category` | 上列分类之一 |
| `titleZh` / `titleEn` | 场景标题 |
| `phraseZh` / `phraseEn` | 可直接说的短句 |
| `noteZh` / `noteEn` | 使用说明（可选） |

**D2.** 再给出 **每景区 2～4 条**专属话术（如云冈「摄影分区」、平遥「古城内交通」），用 `spotSlug` 关联。

**E2.** 写一份「山西文旅概况」短文（zh 300 字内 / en 180 words 内），供「景区概况」页：地理、历史主线（晋商、古建、佛教艺术等）、适合停留天数建议。

**E3.** 若保留「文化遗产」列表：哪些点应出现？与景区列表如何去重？

## F. 数据质量与合规

**F1.** 哪些字段最容易过时？请列出，并建议 Mock 里用什么免责声明文案（zh/en）。

**F2.** 英文专名：给出景区、地名的 **推荐官方/通行拼写**（拼音 vs 惯用英文名），列对照表，避免混用。

**F3.** 内容是否涉及敏感或易争议表述？请标出并给中性改写建议（仍双语）。

## G. 交付格式（请 GPT 严格遵守）

请最终按下列结构汇总（Markdown 即可）：

1. `spotCatalog`：全部候选 + P0/P1  
2. `spots[]`：每个 P0 的完整对象（按 B 字段）  
3. `barrierTypes[]`：障碍类型字典  
4. `serviceItems[]`：通用双语服务条目  
5. `spotServiceLinks[]`：景区专属话术  
6. `homeRecommendations[]`  
7. `provinceIntro`：概况双语  
8. `glossary`：专名中英对照  
9. `sourcesIndex`：来源列表  
10. `openQuestions`：仍无法核实、需人工查官网的问题清单
