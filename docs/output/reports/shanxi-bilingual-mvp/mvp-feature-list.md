# MVP 功能清单 — 山西文旅双语小程序

> theme: `shanxi-bilingual-mvp`  
> status: draft（待你确认后可升为 PRD / 拆 Issue）  
> 依据：产品主线「景区介绍 + 双语服务」；模板能力按需裁剪

## 目标（MVP）

入境游客与中文用户可在小程序中：浏览山西重点景区、切换中/英、阅读文化解读与基础服务指引。不追求完整 OTA（购票/订单非主线）。

## 范围总览

| 优先级 | 模块 | MVP | 说明 |
|---|---|---|---|
| P0 | 语言偏好 / 切换 | ✅ | 全局 zh ↔ en；影响壳文案与景区内容字段 |
| P0 | 景区列表 | ✅ | 山西 Mock 景区；筛选可先做「全部 / 城市或类型」二选一 |
| P0 | 景点详情 | ✅ | 双语介绍、开放信息、文化解读、基础服务信息 |
| P0 | 首页入口 | ✅ | 精简：推荐景区 + 进入列表/概况；弱化无关运营位 |
| P0 | 双语服务条目 | ✅ | 购票问询、礼仪、应急等中英对照（可挂详情或独立「服务」页） |
| P0 | Mock 数据层 | ✅ | 可替换的山西景区 JSON/种子；字段与后端契约对齐 |
| P1 | 管理端景区双语维护 | ✅ 轻量 | 能改 zh/en 与文化解读即可；无复杂工作流 |
| P1 | 景区概况 / 文化遗产 | ⚪ 可选 | 模板已有页；可并入详情「文化解读」以减页 |
| P1 | 推荐位 | ⚪ 可选 | 首页 3～6 个固定推荐即可，不必完整运营后台 |
| P2 | 攻略 | ❌ 延后 | 模板保留但不进 MVP 验收 |
| P2 | 订票 / 订单 / 评论 | ❌ 延后 | 模板可留入口隐藏或标注「演示」 |
| P2 | 天气 / 公交 / 行程规划 | ❌ 延后 | 非双语主线 |
| P2 | 完整登录注册体系 | ❌ 延后 | MVP 可游客浏览；登录非阻塞 |

## P0 功能拆分（建议任务粒度）

| ID | 功能 | 用户价值 | 主要落点 | 验收要点 |
|---|---|---|---|---|
| F1 | 语言切换 | 入境游客可读英文 | `tourism_weapp` 全局状态 + 壳文案字典 | 切换后 Tab/按钮/详情字段同步变化 |
| F2 | 景区列表 | 发现山西景点 | `pages/spot` + Mock/API | ≥ N 个山西景区；名称/封面/城市双语或按语言显示 |
| F3 | 景点详情 | 理解景区与文化 | `pages/spot/detail` | 含简介、开放时间、门票概要、交通概要、文化解读（双语） |
| F4 | 文化解读区块 | 降低跨文化障碍 | 详情内 section | 至少礼仪/历史语境/参观提示三类之一有内容 |
| F5 | 双语服务条目 | 现场沟通辅助 | `pages/service` 精简或详情内 | ≥ 8 条常用中英对照（购票、问路、禁忌、求助等） |
| F6 | 首页精简 | 一键进入主线 | `pages/home` | 突出景区与语言入口；隐藏或降权订票运营 |
| F7 | Mock 数据契约 | 无官方资料可演示 | `docs` 调研结果 → seed/JSON → API | 字段可被管理端/接口替换，不写死在组件里 |

## P1（MVP+，有余力再做）

## 明确不做（本阶段）

- 真实支付购票、库存、核销
- 多语言超过中英（如日/韩）
- 语音讲解、AR、地图深度导航
- 论文正文或学术图表进小程序

## 与模板页面映射

| 模板页 | MVP 策略 |
|---|---|
| home / spot / spot/detail | **改造核心** |
| service | **改造为双语服务**（可砍天气公交入口） |
| introduce / heritage | 内容并入详情或保留只读概况 |
| strategy* / prebook / order* / weather / traffic / plain* | **不验收**；可隐藏 Tab 子入口 |
| user / signin | 非阻塞；可保留模板默认 |
